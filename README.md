# Tuneit

Хроматический тюнер для гитар и бас-гитар с полной библиотекой строёв (83 пресета), эталонными тонами и метрономом. Полностью офлайн: без бэкенда, без сети, без аналитики. Flutter, Android (minSdk 24) и iOS (13+).

## Сборка

Нужен установленный Flutter (stable). Первый запуск на Windows — двойной клик по `setup.bat` (вся логика в `setup.ps1`, вывод пишется в `setup_log.txt`). Скрипт сам находит Flutter, генерирует платформенные папки (`flutter create`), добавляет разрешение `RECORD_AUDIO` в Android-манифест и `NSMicrophoneUsageDescription` в iOS Info.plist, ставит зависимости, прогоняет `flutter analyze` + `flutter test` и, если по USB подключён Android-телефон с включённой отладкой, сразу собирает и запускает на нём release-сборку. Дальше — обычный `flutter run`.

На macOS/Linux те же шаги вручную: `flutter create --platforms=android,ios --org kz.qoldau --project-name tuneit .`, затем добавить два разрешения в манифесты, `flutter pub get`, `flutter test`, `flutter run`.

Разрешение `INTERNET` в основной манифест сознательно не добавляется: это техническая гарантия, что релизная сборка не ходит в сеть. Все звуки (эталонные тоны, клики метронома) генерируются в рантайме — аудио-ассетов в проекте нет.

## Как это работает

Захват звука — `record` (PCM16, 44.1 кГц, моно, без AGC/шумоподавления). Сырые чанки уходят в отдельный изолят (`lib/audio/pitch_isolate.dart`), где после DC-блокирующего фильтра сигнал нарезается окнами по 4096 сэмплов с 50 % перекрытием (~21 обновление/с) и обрабатывается алгоритмом YIN (`lib/audio/pitch_detector.dart`): разностная функция, CMND, порог с поиском минимума в первой «яме» и параболическая интерполяция лага. На чистом сигнале точность лучше ±0.1 цента, октавных ошибок на низких струнах (B0 и ниже) нет — это закреплено тестами. В UI-изолят возвращаются только готовые тройки «частота/уверенность/RMS»; контроллер (`lib/state/tuner_controller.dart`) добавляет noise gate, медианный фильтр и экспоненциальное сглаживание.

Все строи хранятся как MIDI-номера нот, частоты всегда вычисляются от калиброванного A4 (435–445 Гц), поэтому калибровка автоматически сдвигает каждый строй. Метроном не использует таймеры для звука: несколько тактов рендерятся в один sample-точный WAV-буфер и зацикливаются аудио-движком (дрейф < 5 мс/мин, тоже проверено тестом).

## Где что лежит

```
lib/
  core/        константы, нотная математика (midi <-> Hz <-> имя), темы
  data/        модель, каталог инструментов, таблицы строёв (tunings/*.dart),
               репозитории настроек и кастомных строёв (shared_preferences)
  audio/       YIN, изолят, захват микрофона, генератор WAV, метроном
  state/       ChangeNotifier-контроллеры (tuner / settings / metronome)
  l10n/        локализация ru/en (рукописная, без codegen)
  ui/          экраны: тюнер, выбор строя, редактор кастомных строёв,
               метроном, настройки; переиспользуемые виджеты
test/          юнит- и виджет-тесты
platform_patches/  патчи манифеста и Info.plist, применяются setup.sh
```

## Как добавить инструмент или строй

Новый строй: одна строка в соответствующем файле `lib/data/tunings/*.dart` — `t(_id, 'my_id', 'My Name', 'E2 A2 D3 G3 B3 E4', TuningCategory.open)`. Новый инструмент: файл со списком строёв, запись в `kInstruments` (`lib/data/instruments.dart`) и локализованное имя в `lib/l10n/strings.dart` (компилятор сам напомнит про оба языка). Тест `tunings_test.dart` проверит количество нот, монотонность и уникальность автоматически.

## Замечание о сборке этого кода

Проект написан и алгоритмически верифицирован в облачной песочнице без доступа к Flutter SDK (математика YIN, WAV-генератора и метронома проверена численно на эталонных сигналах через порт в Python). `flutter analyze`/`flutter test` на машине разработчика — первый шаг `setup.sh`; если анализатор что-то найдёт, это будут точечные мелочи, а не архитектурные проблемы.
